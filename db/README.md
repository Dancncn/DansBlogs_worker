# 数据库初始化与升级

新数据库使用 `schema.sql`。它包含评论 `parent_id`、对应索引和图片目录映射表；不要再执行 `0002_add_parent_id.sql`。

旧数据库应先检查 `PRAGMA table_info(comments)`。仅当 `parent_id` 不存在时执行旧 `0002` 迁移，不要对已经包含该字段的数据库重复执行。

`0003_image_namespaces.sql` 是可重复执行的新增表迁移，只创建 `user_image_namespaces`。它不修改已有用户 ID、评论、会话或 R2 对象。应用首次需要用户图片目录时也会用 `CREATE TABLE IF NOT EXISTS` 初始化该表，因此不要求必须先完成迁移才能更新代码。以上说明不代表已执行任何线上迁移。

图片目录使用持久保存的随机 UUID，`user_id` 和 `namespace` 都受唯一约束保护。同一用户并发首次请求通过冲突忽略与重新读取，得到同一个目录。目录不由邮箱、公开用户名、邮箱哈希或签名密钥计算；重启和密钥轮换不改变它。

这张表是图片所有权关联数据，必须与 D1 其他业务表一起备份和恢复。不要清空后重新生成，否则旧图片目录将失去关联。原作者 `posts/`、`misc/` URL 和旧个人图片删除路径保持兼容。
